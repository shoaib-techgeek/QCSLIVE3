# Changelog

## Unreleased
- P2.1 Cart: `GET/POST /api/v1/cart`, `PATCH/DELETE /api/v1/cart/items/{id}`. Grouped by store, revalidated on every read (price changes, unavailable, sold out, not enough stock), per-item quantity limit (`CART_MAX_QTY`, default 10), selection, buyer-only access with 404 on other buyers' items. Storefront: header cart count, "Add to cart" with quantity on the product page (signed-out shoppers are sent to sign in), cart page with change notices and summary. P2 design and decisions in `docs/design/P2-cart-checkout-orders.md`.
- Storefront on the live catalogue (P1.8-P1.10): home shows real "New in" and category-filtered products, search/category page (`/search`) with sort and price filters and "Show more", product page (`/p/:slug`) with photos, option picker and availability. Header search, category menu and footer now go to `/search`. "Best sellers" and "Top rated" were removed until sales and reviews exist.
- Seller center: Products list, add-product form with a variant price table, product page (details, photos, prices and stock, send for review, hide/show, delete). Admin console: product review queue and review page with approve / ask for changes / hide / remove.
- `seed:dev` also creates `seller@example.com` (password in README) with an approved demo store and 8 live products with photos and stock. Dev-only.
- Product slugs and prices are shown as sent by the API; money parsing in forms uses integer minor units only. Brand name is "QCS Store" everywhere (tab title, sidebar, login panel).
- P1.8 Public catalogue API: `GET /api/v1/categories`, `/products` (fulltext + substring search, category and price filters, sort by newest/price/relevance, opaque cursor), `/products/{slug}`, `/stores/{slug}`. Only live products (active, active seller, active SKU); no seller codes, stock numbers or internal ids; browsers always revalidate, shared caches keep it up to 60 s.
- P1.7 Inventory: stock per SKU with reserve, release, commit and expiry release (`InventoryService`), atomic conditional updates so parallel buyers can never oversell (tested with 50 parallel reservations), all-or-nothing multi-line reserves, idempotent per order, append-only stock ledger, `inventory.*` events. Sellers set stock with `PUT /api/v1/seller/skus/{skuId}/stock`; product views show on-hand, reserved and available. `low_stock` is not emitted until a threshold is decided.
- P1.6 Admin product moderation: review queue, product detail with store and history, approve/reject/ban/deactivate with required reasons (`/api/v1/admin/products`), new permission `product:moderate` for the admin role, reviewers can preview images of products that are not live, resubmitting clears the rejection reason.
- P1.5 Seller product API: create/list/read/edit/delete products with options and per-variant SKUs (`/api/v1/seller/products`), price history and `price.changed`, submit/deactivate/activate with approved-seller check, images (JPG/PNG/WebP, max 8) and a media route that serves images publicly only for active products. Config: `PLATFORM_CURRENCY`, `CATALOG_MAX_*`. File type detection moved to `shared/file-sniff.ts`.
- P1.4 Catalog foundations: schema for categories (10 starter categories seeded), products, options, SKUs (price and compare-at CHECKs, per-seller unique SKU code), price and status history; pure rules for the product state machine, variant matrix and price validation; shared `slugify`/`productSlug`. No endpoints yet (P1.5).
- Storefront redesign v3: palette and layout moved to a deal-first marketplace look (white page, red `#B6030C` header, orange `#FB7701` actions, green trust band, black promise bar, system font, small radii). Categories menu in the header, frameless product cards, no awning. Fonts packages are no longer imported.
- Storefront redesign v2 (informed by a read-only look at temu.com's layout): promise bar with the seller link, full-bleed hero, green trust band, two side-by-side rails, interest chips filtering a dense 5-across grid, price-first product cards with sold counts and a verified-seller badge. No fake countdowns, scarcity labels or shipping/price-adjustment claims.
- Storefront redesign: utility bar with a "Sell on QCS Store" link ("Seller center" for approved sellers), search header with the awning, category strip, hero, trust row, category tiles, product shelves (sample data in `src/lib/sampleCatalog.js` until the catalogue API exists), seller recruitment band and footer. Brand text is now "QCS Store".
- P1.3 Seller verification (KYC): document upload (content-sniffed JPG/PNG/PDF, 5 MB), encrypted CNIC/address/NTN, submit with missing-item report, admin queue, audited detail/download, decisions (start review, approve, approve with conditions, reject, request info). Approval activates the store and grants the `seller` role. New roles/permissions: `seller`, `admin`, `seller:access`, `admin:access`, `kyc:review`. `seed:dev` also creates `admin@example.com`.
- Frontend: seller onboarding page (`/seller/onboarding`), admin verification queue and review pages (`/admin/kyc`), "Sell on QCS Store" link on the account page.
- P1.2 KYC foundations: pure KYC state machine (`transitionKyc`, `canPublish`), `Encryptor` (AES-256-GCM) for PII, `FileStorage` (memory + local disk, unsafe keys rejected), env settings `PII_ENCRYPTION_KEY`, `STORAGE_DRIVER`, `STORAGE_DIR` (required/restricted in production).
- P1.1 Seller profile: `POST/GET/PATCH /api/v1/seller/profile` (one store per user, unique name and slug, audit + `seller.registered` event). Design for P1 approved in `docs/design/P1-seller-and-catalog.md`.
- `docs/openapi.yaml` for health and identity endpoints; architecture tests (shared never imports modules, modules never import each other, routes and spec must match).
- Outbox relay: `EventBus`, `relayOnce` (retry, per-consumer dedupe via `processed_events`), `startRelay` wired into the server.
- P0 foundation: `Money` (minor units, half-even percentage, exact allocate), `Clock`/`FixedClock`, transactional outbox table and helpers, `PaymentGateway` interface with `FakePaymentGateway`, GitHub Actions CI.
- Docs: removed duplicate guides and the stale blueprint README; rewrote CLAUDE.md for the real stack; added ADR-0001/0002 and `modules/README.md` with module status.
- Design system: tokens with light/dark/system theme, UI kit (Button, Badge, Field select/textarea, Tabs, Modal, Toast, Skeleton, EmptyState, DataTable, StatCard, ProductCard), `formatMoney` helper, dev-only gallery at `/design`.
- Seller center (`/seller`) and admin console (`/admin`) shells with a responsive sidebar, gated by `seller:access` / `admin:access` (permissions to be added by the backend).
- Backend foundation: Fastify/TypeScript app, env validation, MySQL migrations, health endpoints, audit table.
- Identity: registration, email verification, login/logout with server-side sessions, password reset/change, lockout, rate limiting, permission guard, profile (`/me`).
- Frontend: React auth pages (sign in, register, verify email, forgot/reset password), protected account page with profile and password change.
